## 1. Цель и формируемые компетенции

**Цель** — построить управляемый LLM-пайплайн локализации, в котором перевод задаётся системной
инструкцией, терминологическими ограничениями сегмента, примерами few-shot и JSON-схемой, а
результат проверяется автоматически и точечно исправляется.

| Компетенция | Что проверяется |
|---|---|
| **ОПК-2** | применение генеративного ИИ для локализации образовательного контента |
| **ОПК-9** | использование API и локальных LLM в цифровом образовательном процессе |
| **УК-1** | критическая проверка контекстных, стилистических и терминологических решений модели |
| **УК-6** | документирование промптов, параметров, версий и повторяемости эксперимента |

### Место работы в курсе

```
ЛР № 1  TMX + TBX            ЛР № 2  NMT (Marian, NLLB)        ЛР № 3  LLM-пайплайн             ЛР № 4
повторное использование  ─►  перевод без управления      ─►  перевод с инструкцией,      ─►  метрики качества
перевода                     терминология «как выйдет»       терминами, форматом, repair      BLEU, chrF, COMET
```

Метрики качества (BLEU, chrF, COMET) в ЛР № 3 не считаются — это тема ЛР № 4. Качество здесь
оценивается по соблюдению глоссария, сохранению разметки и экспертному разбору.

## 3. Выбор модели и подключение

Студент выбирает **одну основную модель**; вторая может использоваться дополнительно.

### Локальная модель через Ollama (рекомендуется для Colab)

Ключи не нужны, текст не покидает среду. В блоке 1.1 ноутбука выполняется:

```bash
apt-get install -y zstd pciutils          # нужны установщику Ollama
curl -fsSL https://ollama.com/install.sh | sh
ollama serve &                            # сервер в фоне
ollama pull qwen2.5:7b                    # ≈ 4.7 ГБ, работает на T4
```

```python
from ollama import chat
response = chat(model="qwen2.5:7b", messages=messages, format=SCHEMA,
                options={"temperature": 0, "seed": 42})
raw_answer = response.message.content
```

Версия модели фиксируется по `digest` из `ollama list`.

### GigaChat

```python
from gigachat import GigaChat
from gigachat.models import Chat, Messages, MessagesRole

chat_request = Chat(
    model="GigaChat-2-Max",
    messages=[Messages(role=MessagesRole.SYSTEM, content=system_prompt),
              Messages(role=MessagesRole.USER, content=user_payload)],
    temperature=0.01,
    response_format={"type": "json_schema", "schema": SCHEMA, "strict": True},
)
with GigaChat(credentials=..., scope="GIGACHAT_API_PERS", verify_ssl_certs=False) as client:
    response = client.chat(chat_request)
raw_answer = response.choices[0].message.content
```

* ключ авторизации — в личном кабинете GigaChat API; для физических лиц scope `GIGACHAT_API_PERS`;
* `verify_ssl_certs=False` допустимо в учебной среде; в рабочей установите корневой сертификат НУЦ Минцифры;
* версия модели возвращается в поле `response.model`.

### Yandex AI Studio

```python
from yandex_ai_studio_sdk import AIStudio        # прежнее имя: yandex_cloud_ml_sdk.YCloudML

sdk = AIStudio(folder_id=..., auth=...)
model = (sdk.models.completions("yandexgpt", model_version="latest")
         .configure(temperature=0, max_tokens=800, response_format={"json_schema": SCHEMA}))
result = model.run([{"role": "system", "text": system_prompt},
                    {"role": "user", "text": user_payload}])
raw_answer = result[0].text
```

Нужны идентификатор каталога и API-ключ сервисного аккаунта с ролью `ai.languageModels.user`.
Альтернатива — OpenAI-совместимый эндпоинт `https://llm.api.cloud.yandex.net/v1` с моделью
`gpt://<folder_id>/yandexgpt/latest`.

### Секреты

| Переменная | Для чего |
|---|---|
| `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE` | GigaChat |
| `YANDEX_FOLDER_ID`, `YANDEX_API_KEY` | Yandex AI Studio |

## 4. Ход работы

| Блок | Что делается |
|---:|---|
| 0–1 | установка зависимостей, параметры эксперимента (`PROVIDER`, модель, температура, зерно, версия промптов) |
| 1.1 | запуск Ollama и загрузка модели (при локальном варианте) |
| 2, 2.0 | загрузка артефактов ЛР № 1 и результатов ЛР № 2, разбор TMX/TBX |
| 3 | 12 тестовых сегментов и пул few-shot без пересечения; тип решения для каждого примера |
| 4 | системный промпт, zero-shot инструкция, шаблон repair, стили A и B; термины сегмента; версии и хэши |
| 5 | JSON Schema, модель Pydantic, трёхуровневая проверка ответа |
| 6 | единый вызов модели с повтором при невалидном ответе и трассировкой |
| 7 | три режима — zero-shot, controlled, few-shot — на одних и тех же сегментах |
| 8 | терминологическая QA для всех режимов и NMT из ЛР № 2; ручное подтверждение |
| 9 | проверка разметки, кода, чисел и модальности |
| 10 | targeted repair минимум для 3 сегментов с контролем объёма правки |
| 11 | стиль A (академический) против стиля B (инструктивный) минимум на 3 сегментах |
| 12 | сводная таблица и экспертные решения по 5+ сегментам |
| 13 | отчёт, версии промптов, зависимости, выгрузка |

### Три режима

| Режим | Системная инструкция | Термины сегмента | Примеры |
|---|---|:---:|:---:|
| **zero-shot** | «Переведи и верни JSON» | — | — |
| **controlled** | полная инструкция с доменом варианта | ✓ | — |
| **few-shot** | полная инструкция | ✓ | 2–4 пары «запрос → JSON-ответ» из пула |

Примеры few-shot подаются парами сообщений `user`/`assistant`, где ответ — корректный JSON: так
модель видит и перевод, и точный формат. Параметр `FEWSHOT_STRATEGY = "fuzzy"` подбирает
примеры по сходству с сегментом — так же, как нечёткий поиск в памяти переводов из ЛР № 1.

### JSON-ответ

```json
{
  "segment_id": "s001",
  "translation": "Полётный контроллер стабилизирует планёр во время автономного полёта.",
  "used_terms": [{"source": "flight controller", "target": "полётный контроллер"}],
  "warnings": []
}
```

Проверка трёхуровневая: синтаксис JSON → обязательные поля и типы (Pydantic) → смысловые правила
(совпадение `segment_id`, непустой перевод, доля кириллицы не ниже 50 %). Невалидный ответ
повторно запрашивается с указанием причины; число попыток сохраняется.

### Трассировка (`results/results_llm.jsonl`)

Для каждого вызова: `segment_id`, `provider`, `model`, `model_version`, `mode`, `style`,
`temperature`, `prompt_version`, `prompt_hash`, `source`, `translation`, `used_terms`,
`warnings`, `json_valid`, `attempts`, `errors`, `latency_s`. Секреты не сохраняются.

## 6. Обязательный минимум

1. реальная LLM (облачный API или локальная модель); режим `mock` не засчитывается;
2. не менее **12 одинаковых сегментов** во всех трёх режимах;
3. примеры few-shot **не пересекаются** с тестовыми сегментами;
4. JSON Schema + проверка Pydantic + смысловые проверки;
5. терминологическая QA с ручным подтверждением каждого срабатывания;
6. проверка разметки, кода, чисел и модальности;
7. targeted repair минимум для **3 сегментов** с контролем объёма правки;
8. минимум **3 стилистических сравнения**;
9. минимум **5 содержательных различий** с типом ошибки и аргументацией;
10. фиксация `model`, `model_version`, `temperature`, `seed`, `prompt_version`, хэшей промптов;
11. отсутствие секретов в Git (включая историю коммитов);
12. сопоставление с эталоном ЛР № 1 и, при наличии, с MarianMT и NLLB из ЛР № 2.

## 8. Критерии оценки (20 баллов)

| Критерий | Состав | Баллы |
|---|---|---:|
| **Работоспособность пайплайна** | реальная LLM — 2 · три режима — 2 · JSON-валидация и repair — 2 | **6** |
| **Лингвистическая обработка и валидация** | соблюдение глоссария — 2 · разметка, код, числа, модальность — 2 · валидный JSON — 1 | **5** |
| **Анализ ошибок и аргументация** | 5+ различий — 2 · сравнение режимов и стилей — 2 · вывод — 1 | **5** |
| **Оформление и воспроизводимость** | версии промптов и модели — 1 · README — 1 · зависимости — 1 · отсутствие секретов — 1 | **4** |
| **Итого** |  | **20** |

**Снижения:**

* режим `mock` или заранее записанные ответы вместо реальной модели — работа не засчитывается;
* ключ или токен в репозитории или его истории — −4 балла и обязательный отзыв ключа;
* примеры few-shot пересекаются с тестовыми сегментами — −2 балла;
* в промпт передаётся весь глоссарий вместо терминов сегмента — −1 балл;
* ручные колонки не заполнены — −2 балла;
* не указаны версия модели и хэши промптов — −1 балл.

## 10. Типичные ошибки

| Ошибка | Следствие | Как избежать |
|---|---|---|
| Примеры few-shot взяты из тестовых сегментов | few-shot «угадывает» ответ, сравнение режимов недостоверно | брать примеры только из пула; в коде стоит проверка |
| Весь глоссарий в каждом запросе | длинный запрос, рост стоимости, размытое внимание | `relevant_terms()` — только термины сегмента |
| Проверка терминов подстрокой | ложные нарушения из-за падежей | сравнение по основам + ручное подтверждение |
| Замена терминов `str.replace()` | несогласованные падежи («проверяет наземная станция») | repair через модель, проверка кодом |
| Доверие JSON без проверки | пустой перевод или ответ на другом языке | трёхуровневая проверка |
| Температура выше 0 | результаты режимов несравнимы между запусками | `temperature=0` (GigaChat — 0.01) и фиксированное зерно |
| Не зафиксирована версия модели | повторить эксперимент невозможно | `digest` Ollama или поле версии в ответе API |
| Ключ в коде ноутбука | компрометация ключа | Colab Secrets или `.env` вне репозитория |
| Персональные данные в облачном API | нарушение 152-ФЗ | такие тексты — только в локальную модель |
