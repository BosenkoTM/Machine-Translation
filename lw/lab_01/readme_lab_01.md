## 2. Структура стандартов (схемы)

### 2.1. TBX — TermBase eXchange (ISO 30042)

Организация **по понятиям** (concept-oriented): одна статья `termEntry` описывает
одно понятие, языковые эквиваленты лежат в отдельных секциях `langSet`.

```
martif [type="TBX", xml:lang]
├── martifHeader
│   ├── fileDesc → titleStmt → title
│   ├── fileDesc → sourceDesc → p
│   └── encodingDesc → p [type="XCSURI"]
└── text
    └── body
        └── termEntry [id]
            ├── descrip [type="subjectField"]
            └── langSet [xml:lang]
                ├── tig                    (компактная группа термина)
                │   ├── term
                │   ├── termNote [type="partOfSpeech"]
                │   └── descrip [type="definition"]
                └── ntig → termGrp         (расширенная группа термина)
                    ├── term
                    └── termNote
```

| Элемент | Обязателен | Назначение |
|---------|:---:|------------|
| `martif` | да | корень документа TBX-Core v2 |
| `termEntry` | да | терминологическая статья (понятие) |
| `langSet` | да (≥ 2) | языковая секция; язык — в атрибуте `xml:lang` |
| `tig` / `ntig` | да | компактная / расширенная группа термина |
| `term` | да | текст термина |
| `termNote` | нет | помета (`partOfSpeech`, `usage`, `administrativeStatus`) |
| `descrip` | нет | `definition`, `subjectField`, `context` |

> **Важно для этой лабораторной работы.** Эталонный `lab_01_teacher.ipynb` и
> автопроверка используют учебный TBX v2-совместимый формат с корнем `martif`.
> Поэтому файл варианта рекомендуется создавать именно в этой структуре.
> **TBX v3 (ISO 30042:2019)** использует корень `tbx`, пространства имён,
> публичные диалекты (`TBX-Core`, `TBX-Min`, `TBX-Basic`) и RNG-схемы. TBX v3
> рассматривается как современное развитие стандарта; его поддержка в парсере
> может быть выполнена как дополнительное расширение.

### 2.2. TMX — Translation Memory eXchange 1.4b

Организация **по сегментам** (segment-oriented): единица хранения — выровненная
пара предложений.

```
tmx [version="1.4"]
├── header [creationtool, creationtoolversion, segtype, o-tmf,
│           adminlang, srclang, datatype, creationdate]
└── body
    └── tu [tuid, creationdate, changedate]
        ├── prop [type="domain" | "client" | "project"]
        ├── note
        └── tuv [xml:lang]
            └── seg
                └── inline-теги: ph, bpt, ept, it, hi
```

| Элемент | Обязателен | Назначение |
|---------|:---:|------------|
| `header` | да | метаданные памяти, язык оригинала (`srclang`), тип сегментации |
| `tu` | да | translation unit — единица перевода |
| `tuv` | да (≥ 1) | вариант сегмента на одном языке (`xml:lang`) |
| `seg` | да | текст сегмента |
| `prop` | нет | произвольное свойство единицы перевода |

> **Важно:** атрибут `xml:lang` принадлежит зарезервированному пространству имён,
> поэтому в парсере он читается как
> `{http://www.w3.org/XML/1998/namespace}lang`, а не как `lang`.
> Текст сегмента следует собирать через `"".join(seg.itertext())`, иначе при
> наличии инлайновых тегов часть текста будет потеряна.

## 3. Ход работы

### Этап 1. Парсинг и валидация TBX

Реализовать `parse_tbx(file_path) -> pd.DataFrame`: обойти `termEntry`, для
каждой `langSet` определить язык по `xml:lang`, извлечь `term`, `termNote`,
`descrip`. Обработать обе формы записи — `tig` и `ntig/termGrp`. Отдельно
реализовать структурную валидацию: наличие корня `martif`, секции
`text/body`, не менее двух языковых секций в статье, непустой `term` в каждой.
Результат — таблица `entry_id | source_term | target_term | pos | definition |
subject_field`.

### Этап 2. Парсинг TMX

Реализовать `parse_tmx(file_path) -> pd.DataFrame`: обойти `tu`, собрать `tuv`
по языкам, извлечь текст `seg`, нормализовать пробелы. Сохранить порядок
следования единиц перевода и добавить колонку `prev_source` — она понадобится
для контекстного сопоставления. Результат — таблица `tuid | source_segment |
target_segment | domain | src_len | prev_source`.

### Этап 3. Fuzzy Search по сегментам

Реализовать метрики сходства и поиск:

* `levenshtein_ratio(a, b) = (1 − d(a, b) / max(|a|, |b|)) · 100`;
* `token_sort_ratio(a, b)` — то же по нормализованным и отсортированным токенам
  (нечувствителен к перестановке слов);
* итоговый `score = max(levenshtein_ratio, token_sort_ratio)`;
* нормализация перед сравнением: NFKC, нижний регистр, удаление пунктуации,
  схлопывание пробелов.

Классификация результата:

| Диапазон | Тип | Действие переводчика |
|----------|-----|----------------------|
| 100 % и совпал предыдущий сегмент | **ICE (101 %)** | подстановка без правки |
| 100 % | Exact | проверить контекст |
| 95–99 % | High Fuzzy | косметическая правка |
| 75–94 % | Fuzzy | редактирование |
| < 75 % | No Match | перевод с нуля |

Выдача сортируется по убыванию `score`, ограничивается параметром `top_n`.

### Этап 4. Генерация билингвального словаря и подстановка терминов

Реализовать `apply_term_glossary(text, glossary_df) -> str`: найти в тексте
термины глоссария и разметить их переводными эквивалентами. Требования:
регистронезависимый поиск строго по границам слов, обработка терминов в порядке
убывания длины (многословный термин имеет приоритет над односложным), защита уже
размеченных фрагментов от повторной подстановки.

### Этап 5. Экспорт и импорт в Smartcat

Выгрузить глоссарий в CSV (`UTF-8` с BOM, колонки `Source (en)`, `Target (ru)`,
`Comment`), сформировать отчёт по найденным совпадениям. Импортировать CSV в
раздел «Глоссарии» Smartcat, а `.tmx` — в раздел «Память переводов», приложить
скриншот результата импорта.

#### Правила подготовки TBX: минимум 15 терминов EN–RU

Для лабораторной работы **термин** — это слово или устойчивое словосочетание,
которое обозначает понятие выбранной предметной области. Случайные
общеупотребительные слова (`system`, `good`, `make`) без специального значения
не засчитываются как качественные терминологические единицы.

Требования к данным:

1. Подготовить не менее **15 различных понятий** по теме своего варианта.
2. **Один `termEntry` = одно понятие.** Внутри него должны присутствовать
   английская и русская языковые секции.
3. Для каждой записи обязательно указать:
   - английский термин (`xml:lang="en"`);
   - русский эквивалент (`xml:lang="ru"`);
   - часть речи (`partOfSpeech`);
   - краткое определение понятия;
   - предметную область (`subjectField`).
4. Термин и его перевод должны обозначать **одно и то же понятие**, а не быть
   буквальным переводом без проверки профессионального употребления.
5. Не использовать дубликаты, различающиеся только регистром, числом или
   пунктуацией. Синонимы допускаются, но основной эквивалент должен быть
   выбран явно.
6. Допускаются и рекомендуются многословные термины (`translation memory`,
   `inertial measurement unit`, `access control list`): они полезны для проверки
   алгоритма подстановки по границам слов.
7. Термины следует брать из **учебной, научной, нормативной или технической
   литературы по своей предметной области**. В конце ноутбука указать не менее
   **2 источников**, по которым проверялась терминология.
8. Для совместимости с эталонным ноутбуком использовать TBX v2-совместимую
   структуру `martif → text → body → termEntry → langSet → term`.

Минимальная логика одной записи:

```xml
<termEntry id="t01">
  <descrip type="subjectField">Machine Learning</descrip>
  <langSet xml:lang="en">
    <tig>
      <term>training dataset</term>
      <termNote type="partOfSpeech">noun</termNote>
      <descrip type="definition">Dataset used to fit model parameters.</descrip>
    </tig>
  </langSet>
  <langSet xml:lang="ru">
    <tig>
      <term>обучающая выборка</term>
    </tig>
  </langSet>
</termEntry>
```

#### Правила подготовки TMX: минимум 10 параллельных предложений EN–RU

В TMX хранится не список отдельных слов, а **память переводов** — пары
выровненных сегментов. В данной работе один сегмент рекомендуется делать равным
одному предложению (`segtype="sentence"`). Спецификация TMX 1.4b прямо
рекомендует сегментацию на уровне предложений для лучшей переносимости между
системами.

Требования к данным:

1. Подготовить не менее **10 уникальных пар предложений EN–RU** по предметной
   области своего варианта.
2. Каждая единица перевода `<tu>` должна содержать как минимум две секции
   `<tuv>`: `xml:lang="en"` и `xml:lang="ru"`, внутри каждой — непустой `<seg>`.
3. Английский и русский сегменты должны быть **семантически эквивалентны**:
   сохраняются факты, числа, единицы измерения, названия объектов и
   причинно-следственные отношения.
4. Не использовать десять несвязанных шаблонных фраз. Предложения должны
   действительно относиться к выбранной профессиональной области.
5. Желательно, чтобы не менее **5 предложений** содержали термины из созданного
   TBX-глоссария — это позволяет проверить совместную работу TM и TermBase.
6. Для демонстрации **ICE** расположить как минимум два логически связанных
   предложения последовательно. В данной лабораторной порядок `<tu>`
   используется как упрощённая модель предыдущего контекста (`prev_source`).
   Это **учебное соглашение**: стандарт TMX сам по себе не задаёт семантику
   порядка единиц `<tu>`.
7. Для демонстрации **Fuzzy Match 75–99 %** взять одно предложение из своей TM
   и сформировать поисковый запрос, изменив в нём 1–2 слова, число или короткий
   фрагмент. Сам исходный сегмент в TMX при этом не менять.
8. Для демонстрации **No Match** использовать отдельное предложение, явно не
   совпадающее с содержимым памяти перевода.
9. Каждому `<tu>` присвоить уникальный `tuid`; в `header` указать
   `srclang="en"`, `segtype="sentence"`, `datatype="PlainText"`.
10. Файл должен быть корректным XML в UTF-8 и полностью разбираться функцией
    `parse_tmx()` без ручного исправления после запуска.

Минимальная единица перевода:

```xml
<tu tuid="001">
  <prop type="domain">Machine Learning</prop>
  <tuv xml:lang="en">
    <seg>The training dataset contains labelled examples.</seg>
  </tuv>
  <tuv xml:lang="ru">
    <seg>Обучающая выборка содержит размеченные примеры.</seg>
  </tuv>
</tu>
```

> **Важно:** допускается подготовить исходные пары в виде списков Python, как
> показано в `lab_01_teacher.ipynb`, и программно сформировать XML. Оценивается
> не ручной набор XML как таковой, а корректность структуры, качество данных,
> работа парсеров и последующая обработка.

| **6** | Реализация алгоритма Fuzzy Match | метрика Левенштейна и Token Sort Ratio, поиск совпадений 75–99 %, различение 100 % Exact и 100 % In-Context Exact Match (ICE), ранжирование выдачи, отсечение по порогу, демонстрация ICE / Fuzzy / No Match |
| **4** | Интеграция глоссария с симуляцией подстановки терминов при переводе | поиск по границам слов, регистронезависимость, приоритет длинных терминов, отсутствие вложенных подстановок, демонстрация минимум на 3 сегментах, корректный экспорт CSV |
| **2** | Оформление отчёта и репозитория | PEP 8, типизация, docstrings, осмысленные выводы, указаны источники терминологии, структура репозитория, пройденные автотесты, сохранённые результаты выполнения |

**Максимум: 20 баллов.**

**Штрафы:** невыполнение требований к объёму данных (< 15 терминов / < 10
сегментов) — до −2 баллов; невалидный XML — до −2 баллов; ноутбук не
запускается последовательно «сверху вниз» без ручного исправления — до −4 баллов.
Штрафы применяются в пределах соответствующего критерия и не могут уменьшить
итог ниже 0 баллов.

## 8. Рекомендуемые стандарты и литература

При подготовке TBX/TMX студенту следует ориентироваться прежде всего на
спецификации форматов, а предметные термины проверять по профильной научной,
учебной и нормативной литературе своего варианта.

1. **ISO 30042:2019.** *Management of terminology resources — TermBase eXchange
   (TBX).* — International Organization for Standardization, 2019. — URL:
   https://www.iso.org/standard/62510.html (дата обращения: 06.09.2026).
2. **TBX Info.** *Introduction to TermBase eXchange (TBX).* — LTAC Global. —
   URL: https://www.tbxinfo.net/ (дата обращения: 06.09.2026).
3. **TBX Info.** *TBX Dialects: TBX-Core, TBX-Min, TBX-Basic.* — URL:
   https://www.tbxinfo.net/tbx-dialects/ (дата обращения: 06.09.2026).
4. **Savourel, Y.** *TMX 1.4b Specification.* — Localization Industry Standards
   Association / GALA, 2005. — URL: https://www.gala-global.org/tmx-14b
   (дата обращения: 06.09.2026).
5. **Microsoft Learn.** *Maintain translation memories.* — URL:
   https://learn.microsoft.com/en-us/globalization/localization/translation-memories
   (дата обращения: 06.09.2026).

> Эти источники описывают **форматы и правила обмена данными**. Конкретные
> английские и русские термины студент подбирает по литературе именно своей
> предметной области и указывает использованные профильные источники отдельно.
