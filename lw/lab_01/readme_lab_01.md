# Лабораторная работа №1

## Компьютерная лексикография, терминологические базы (TBX) и Translation Memory (TMX) в Smartcat

**Курс:** «Основы машинного перевода»

**Инструменты:** Python 3.10+, Google Colab, `xml.etree.ElementTree` / `lxml`, `Levenshtein` / `thefuzz`, `pandas`

**Языковая пара:** EN → RU

---

## 1. Цель работы

Изучение стандартов обмена терминологическими данными (TBX v2/v3) и базами памяти

переводов (TMX 1.4b), программная обработка и валидация XML-структур, расчёт

коэффициентов нечёткого совпадения (Fuzzy Match / Levenshtein Distance),

интеграция и экспорт глоссариев в CAT-системы (Smartcat).

**Задачи:**

1. Разобрать и валидировать XML-схему терминологической базы TBX.
2. Извлечь параллельные сегменты из памяти переводов TMX.
3. Реализовать метрику сходства строк и поиск нечётких совпадений с ранжированием.
4. Реализовать автоматическую подстановку терминов глоссария в исходный текст.
5. Экспортировать результаты в формате, пригодном для импорта в Smartcat.

## 2. Структура стандартов (схемы)

### 2.1. TBX — TermBase eXchange (ISO 30042)

Организация **по понятиям** (concept-oriented): одна статья `termEntry` описывает
одно понятие, языковые эквиваленты лежат в отдельных секциях `langSet`.

```
martif [type="TBX", xml:lang]
├── martifHeader
│   ├── fileDesc → titleStmt → title
│   ├── fileDesc → sourceDesc → p
│   └── encodingDesc → p [type="XCSURI"]
└── text
    └── body
        └── termEntry [id]
            ├── descrip [type="subjectField"]
            └── langSet [xml:lang]
                ├── tig                    (компактная группа термина)
                │   ├── term
                │   ├── termNote [type="partOfSpeech"]
                │   └── descrip [type="definition"]
                └── ntig → termGrp         (расширенная группа термина)
                    ├── term
                    └── termNote
```

| Элемент | Обязателен | Назначение |
|---------|:---:|------------|
| `martif` | да | корень документа TBX-Core v2 |
| `termEntry` | да | терминологическая статья (понятие) |
| `langSet` | да (≥ 2) | языковая секция; язык — в атрибуте `xml:lang` |
| `tig` / `ntig` | да | компактная / расширенная группа термина |
| `term` | да | текст термина |
| `termNote` | нет | помета (`partOfSpeech`, `usage`, `administrativeStatus`) |
| `descrip` | нет | `definition`, `subjectField`, `context` |

> **TBX v3 (2019)** заменяет `martif` на `tbx`, вводит модули (`TBX-Core`,
> `TBX-Min`, `TBX-Basic`) и RNG-схемы вместо DTD. Логика обхода дерева
> (`termEntry → langSet → term`) сохраняется, меняются только имена корня и
> некоторых обёрток; парсер следует писать устойчивым к обоим вариантам.

### 2.2. TMX — Translation Memory eXchange 1.4b

Организация **по сегментам** (segment-oriented): единица хранения — выровненная
пара предложений.

```
tmx [version="1.4"]
├── header [creationtool, creationtoolversion, segtype, o-tmf,
│           adminlang, srclang, datatype, creationdate]
└── body
    └── tu [tuid, creationdate, changedate]
        ├── prop [type="domain" | "client" | "project"]
        ├── note
        └── tuv [xml:lang]
            └── seg
                └── inline-теги: ph, bpt, ept, it, hi
```

| Элемент | Обязателен | Назначение |
|---------|:---:|------------|
| `header` | да | метаданные памяти, язык оригинала (`srclang`), тип сегментации |
| `tu` | да | translation unit — единица перевода |
| `tuv` | да (≥ 1) | вариант сегмента на одном языке (`xml:lang`) |
| `seg` | да | текст сегмента |
| `prop` | нет | произвольное свойство единицы перевода |

> **Важно:** атрибут `xml:lang` принадлежит зарезервированному пространству имён,
> поэтому в парсере он читается как
> `{http://www.w3.org/XML/1998/namespace}lang`, а не как `lang`.
> Текст сегмента следует собирать через `"".join(seg.itertext())`, иначе при
> наличии инлайновых тегов часть текста будет потеряна.

## 3. Ход работы

### Этап 1. Парсинг и валидация TBX

Реализовать `parse_tbx(file_path) -> pd.DataFrame`: обойти `termEntry`, для
каждой `langSet` определить язык по `xml:lang`, извлечь `term`, `termNote`,
`descrip`. Обработать обе формы записи — `tig` и `ntig/termGrp`. Отдельно
реализовать структурную валидацию: наличие корня `martif`, секции
`text/body`, не менее двух языковых секций в статье, непустой `term` в каждой.
Результат — таблица `entry_id | source_term | target_term | pos | definition |
subject_field`.

### Этап 2. Парсинг TMX

Реализовать `parse_tmx(file_path) -> pd.DataFrame`: обойти `tu`, собрать `tuv`
по языкам, извлечь текст `seg`, нормализовать пробелы. Сохранить порядок
следования единиц перевода и добавить колонку `prev_source` — она понадобится
для контекстного сопоставления. Результат — таблица `tuid | source_segment |
target_segment | domain | src_len | prev_source`.

### Этап 3. Fuzzy Search по сегментам

Реализовать метрики сходства и поиск:

* `levenshtein_ratio(a, b) = (1 − d(a, b) / max(|a|, |b|)) · 100`;
* `token_sort_ratio(a, b)` — то же по нормализованным и отсортированным токенам
  (нечувствителен к перестановке слов);
* итоговый `score = max(levenshtein_ratio, token_sort_ratio)`;
* нормализация перед сравнением: NFKC, нижний регистр, удаление пунктуации,
  схлопывание пробелов.

Классификация результата:

| Диапазон | Тип | Действие переводчика |
|----------|-----|----------------------|
| 100 % и совпал предыдущий сегмент | **ICE (101 %)** | подстановка без правки |
| 100 % | Exact | проверить контекст |
| 95–99 % | High Fuzzy | косметическая правка |
| 75–94 % | Fuzzy | редактирование |
| < 75 % | No Match | перевод с нуля |

Выдача сортируется по убыванию `score`, ограничивается параметром `top_n`.

### Этап 4. Генерация билингвального словаря и подстановка терминов

Реализовать `apply_term_glossary(text, glossary_df) -> str`: найти в тексте
термины глоссария и разметить их переводными эквивалентами. Требования:
регистронезависимый поиск строго по границам слов, обработка терминов в порядке
убывания длины (многословный термин имеет приоритет над односложным), защита уже
размеченных фрагментов от повторной подстановки.

### Этап 5. Экспорт и импорт в Smartcat

Выгрузить глоссарий в CSV (`UTF-8` с BOM, колонки `Source (en)`, `Target (ru)`,
`Comment`), сформировать отчёт по найденным совпадениям. Импортировать CSV в
раздел «Глоссарии» Smartcat, а `.tmx` — в раздел «Память переводов», приложить
скриншот результата импорта.

## 5. Критерии оценки (10 баллов)

| Баллы | Критерий | Что проверяется |
|:--:|----------|-----------------|
| **2** | Парсинг и валидация схемы TBX-глоссария | корректный обход `termEntry → langSet → term`, чтение `xml:lang`, поддержка `tig` и `ntig`, отчёт валидации без ложных срабатываний, DataFrame требуемой структуры |
| **2** | Извлечение пар сегментов из TMX памяти перевода | корректный обход `tu → tuv → seg`, устойчивость к инлайновым тегам, сохранение порядка сегментов и колонки `prev_source` |
| **3** | Реализация алгоритма Fuzzy Match | метрика Левенштейна и Token Sort Ratio, поиск совпадений 75–99 %, различение 100 % Exact и 100 % In-Context Exact Match (ICE), ранжирование выдачи, отсечение по порогу |
| **2** | Интеграция глоссария с симуляцией подстановки терминов при переводе | поиск по границам слов, регистронезависимость, приоритет длинных терминов, отсутствие вложенных подстановок, демонстрация на 3+ сегментах |
| **1** | Оформление отчёта и репозитория | PEP 8, типизация, docstrings, осмысленные выводы, структура репозитория, пройденные автотесты |

**Штрафы:** невыполнение требований к объёму данных (< 15 терминов / < 10
сегментов) — −1 балл; невалидный XML — −1 балл; ноутбук не запускается «в один
клик» — −2 балла.
